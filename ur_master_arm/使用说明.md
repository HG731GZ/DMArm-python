# 艾利特同构主端机械臂

模型来自 SolidWorks 当前打开的 `总装.SLDASM`。同一装配的 37 个零件实例组成固定底座与 6 个活动连杆。末端联轴器和示教器随第六轴运动，示教器夹钳保持装配时的开合姿态。普通末端把手和 Delta 附件在源配置中已压缩。

## 加载

- `ur_master_arm.urdf` 为 URDF 入口。网格相对于 URDF 定位。
- `ur_master_arm.xml` 为 MuJoCo 的 MJCF 入口。可在该目录运行 `python -m mujoco.viewer --mjcf ur_master_arm.xml`。
- 移动或复制时请保留同级 `meshes` 目录。两个模型共用 22 个外观网格和 22 个逐零件凸包碰撞网格，长度单位均为米。碰撞凸包会填平零件上的孔和凹槽。

## 坐标和关节

`base_link` 对应 SolidWorks 的 `World`，`DH1` 至 `DH6` 是各活动连杆的局部坐标系。`joint1` 至 `joint6` 分别绕对应 DH 坐标系的 +Z 轴按右手定则转动，角度单位为弧度。六轴读数全为零时重现导出时的装配姿态。下表位置均在 World 中，以米计。

| 坐标系 | 零位原点 (X, Y, Z) | 零位转轴方向 (X, Y, Z) |
| --- | --- | --- |
| DH1 | (0, 0, 0.13575) | (0, 0, 1) |
| DH2 | (0, 0, 0.13575) | (0, −1, 0) |
| DH3 | (0, 0, 0.34575) | (0, −1, 0) |
| DH4 | (0, −0.062, 0.54575) | (0, −1, 0) |
| DH5 | (0, −0.062, 0.61875) | (0, 0, 1) |
| DH6 | (0, −0.098, 0.61875) | (0, −1, 0) |

## 在 DMArm 主窗中查看

Windows x64 的 `dmarm` 环境使用 conda-forge 的 Pinocchio 4.1.0。安装命令为 `conda install -n dmarm -c conda-forge pinocchio-python=4.1.0`。在 PyCharm 中选择该环境的解释器即可运行项目根目录的 `main.py`。

运行项目根目录的 `main.py`，可在“主从实体姿态”中查看两端的姿态。主端使用蓝色实心模型，从端使用橙色半透明模型。两端都在等待数据时，灰色模型展示装配零位。左键拖动可旋转，滚轮可缩放，双击恢复默认视角。`main.py` 顶部的 `SLAVE_MODEL_OPACITY` 控制从端不透明度，默认值为 0.40。

世界坐标系固定在底座底面的 `base_link`，两端的末端坐标系分别跟随各自的 `DH6`。红、绿、蓝依次表示 X、Y、Z 正方向。主端末端轴使用实线，从端使用虚线。

控制侧 DH 基座位于第一关节轴心，比模型世界原点高 0.13575 m。上表的 CAD 装配零位对应主窗关节角 `(0°, −90°, 0°, −90°, 0°, 0°)`。主窗用 Pinocchio 的 CAD 连杆世界位姿绘制网格，控制 DH2、DH3 相对各自的 CAD 系绕局部 Z 轴转半周。六轴重力前馈使用同一份 URDF 的质量和质心，控制线程有独立的计算数据。

## 仿真参数

质量、质心和惯量取自 SolidWorks 质量属性，包括 CAD 中已有的质量覆盖值。整臂质量为 3.717371 kg。六个关节均按被动、连续旋转建模。机械行程、速度、驱动力矩和摩擦参数需依据实机数据补充。

已在 MuJoCo 中加载 MJCF 并完成 2 秒动力学步进。URDF 已用 yourdfpy 加载外观和碰撞几何。对照装配体坐标系检查了零位及 64 组非零关节姿态下的六个连杆位姿。

## Pinocchio 离线评估（2026-11-27）

迁移验收时，在项目的 `dmarm` 环境分别加载了修正示教器装配后的 URDF 和 MJCF。两者均复现了迁移前的六连杆正运动学，静态重力矩差异在 10⁻⁵ N·m 量级。主端已通过实机验收。

### 坐标和数值

用同一组六个控制侧 DH 角比较。模型关节角等于控制角减去装配姿态 `(0, −π/2, 0, −π/2, 0, 0)`。在 Pinocchio 4.1.0 中，URDF 的六个连续关节以六对余弦、正弦表示，配置维数为 12。MJCF 的六个铰链各用一个角度，配置维数为 6。两者的速度和广义力矩均为六维。脚本用 `pin.integrate(model, neutral, q_dh - assembly)` 生成各自的配置。

比较 `T10` 至 `T60` 时，采用主窗已有的固定配准，将模型位姿转回控制侧。控制基座在模型基座上方 135.75 mm，DH2、DH3 的局部 X、Y 轴相对 CAD 反向。重力统一设为 `(0, 0, −9.80665) m/s²`。Pinocchio 的关节抗重力矩按现有传动比换到电机侧，J3 反号。下表力矩均为施加控制器倍率前的值。

数值样本包含本机 `teleop_20261126_174349_621376.csv` 中的 19,274 帧完整主端角度、在各轴 `[−π, π]` 独立均匀抽取的 4,096 组角度，以及控制零位、CAD 装配位和项目预设位。随机种子为 20261127。

| 相对迁移前算法的最大差值 | Pinocchio + URDF | Pinocchio + MJCF |
| --- | ---: | ---: |
| 六个连杆原点的位置差 | 1.26 × 10⁻¹³ m | 5.12 × 10⁻¹⁴ m |
| 六个连杆坐标系的转角差 | 5.83 × 10⁻¹³ rad | 2.54 × 10⁻¹³ rad |
| 日志中单轴电机重力矩绝对差 | 6.67 × 10⁻⁶ N·m | 6.67 × 10⁻⁶ N·m |
| 全角域采样及三个基准姿态中单轴电机重力矩绝对差 | 1.43 × 10⁻⁵ N·m | 1.43 × 10⁻⁵ N·m |

在控制侧 DH6 坐标系中，J6 的旧质心为 `(−0.290000, 9.891000, 37.114000) mm`，修正后的 CAD 质心为 `(−0.289785, 9.891162, 37.114282) mm`，相距 0.000390 mm。在 URDF 内存副本中使用旧代码的六连杆质量和质心后，所有样本的最大重力矩差降至 8.69 × 10⁻¹³ N·m。

项目预设位的 J4 电机重力矩为 0.4959591 N·m，旧算法为 0.4959573 N·m。以当前各轴倍率和轴开关计算纯重力前馈，两批输入中单轴指令最大浮点差为 1.58 × 10⁻⁵ N·m。

两份文件加载后的六个活动连杆总质量均为 3.0931451 kg。逐连杆与各自文件的惯量张量核对，最大元素差为 4.34 × 10⁻¹⁹ kg·m²。现有主端的刚体动力学只计算静态重力矩。对 4,096 组全角域样本另取相同的关节速度（±1 rad/s）和加速度（±3 rad/s），两个文件算出的重力矩、质量矩阵（CRBA）、逆动力学（RNEA）最大元素差分别为 9.56 × 10⁻¹³ N·m、4.03 × 10⁻¹⁴ kg·m²、9.79 × 10⁻¹³ N·m。项目的从端自由空间预测器使用从端日志辨识的时延、加速和制动参数，属于另一项计算。[Pinocchio 刚体算法文档](https://gepetto.github.io/doc/pinocchio/doxygen-html/)

### 修正前模型的本机计时记录

测量环境为 Windows 10 x64、Intel Core i7-11800H、Python 3.10.22、NumPy 2.2.6。项目环境从 conda-forge 安装了 `pinocchio-python` 4.1.0。每格为一次完整测量中单次调用的中位数 / 第 95 百分位，单位 µs。

| 相同输入和输出 | 迁移前实现 | Pinocchio + URDF | Pinocchio + MJCF |
| --- | ---: | ---: | ---: |
| DH 角 → 六轴电机重力矩 | 9.7 / 10.0 | 5.4 / 5.6 | 5.0 / 5.2 |
| 六轴电机反馈 → 带倍率和轴开关的前馈指令 | 19.2 / 19.8 | 14.4 / 15.1 | 14.0 / 14.8 |
| DH 角 → 六个控制侧位姿 | 47.1 / 48.6 | 28.1 / 28.9 | 27.7 / 28.8 |
| DH 角 → 六个控制侧位姿及电机重力矩 | 61.3 / 70.8 | 30.5 / 33.9 | 30.3 / 41.8 |

每种实现先预热，再对相同的 512 个日志样本和 512 个全角域样本测量 12 轮，每轮轮换实现的执行顺序。计时包含各行所需的关节编码、电机力矩换算和位姿矩阵输出。正运动学单项使用现有 `Robot_UR` 构造器，计时期间跳过末尾的重力计算。模型解析和 `Data` 分配在预热前完成。CAN 收发、Qt 绘制和日志读取均在计时范围之外。

当时另一次独立测量中，现有项目与 URDF 的前馈中位耗时分别为 21.4 和 16.2 µs，六个位姿加重力矩分别为 59.4 和 29.7 µs。两次运行中，URDF 的前馈计算均节约约四分之一的耗时，实际 CAN 周期还取决于通信和调度。
